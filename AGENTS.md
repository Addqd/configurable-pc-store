# PC Builder & Store — project AGENTS.md

> Дополнение к глобальному AGENTS.md пользователя Pi, не замена и не копия. Сначала прочти действующие глобальные правила и этот файл, затем `.agent/PROJECT.md` и относящиеся к задаче документы. Если проектные файлы отсутствуют — не выдумывай их содержание.

## Источник истины и scope

- Прямые актуальные указания владельца имеют приоритет над документами и старыми UI-референсами.
- Перед правками проведи **минимальное read-only исследование** реальных файлов, lockfiles и доступных инструментов **без каких-либо операций с Git/GitHub**. Не утверждай, что что-либо реализовано/установлено/протестировано, без доказательства.
- Меняй только файлы и поведение, необходимые для конкретной задачи; не расширяй функции, не добавляй зависимости, не перестраивай архитектуру и не меняй дизайн по собственной инициативе.
- Утверждённые продуктовые решения изложены в `.agent/PROJECT.md`, `docs/PRODUCT_REQUIREMENTS.md`, `docs/UI_SPEC.md`; технологические границы — в `docs/ARCHITECTURE.md`.
- `docs/references/pcbuilder/` содержит PNG-**образцы**, а не готовые элементы приложения. Референсы не заменяют HTML/CSS-компоненты. Сверяй подписи и точные имена по `docs/references/README.md`.

## Задача, skills, контрольные точки

1. Перед изменениями implementation/config обнови **`.agent/TASK.md`**, создай проверяемые acceptance criteria и зафиксируй требуемые проверки. Этот файл предназначен только для текущей задачи и **не коммитится**.
2. Найди только релевантные установленные Pi skills, последовательно **открой и полностью прочитай** их реальные `SKILL.md` до реализации. Не считай их автоматически применёнными из-за наличия в списке.
3. Перечитывай релевантные skills на границах этапов: архитектура/модель, API/валидация, безопасность, UI и тесты/проверка перед завершением — по применимости.
4. Если требуются актуальные API сторонней библиотеки, сверяй реальные установленные версии и документацию (Context7 по необходимости), не придумывай CLI-флаги или функции.
5. При потере/сжатии контекста перечитай `.agent/TASK.md` и текущие локальные факты, не реконструируй результат по памяти.

## Что считать готовым

- Для React/UI: проверяй реальный рендер через доступный `pi-frontend-check` (`frontend_open`, `frontend_act`, `frontend_screenshot`, `frontend_eval`, `frontend_console`). Смотри **новый** скриншот после визуальных правок, проверяй интерактивность, console и требуемые viewport. Сборка и DOM-дерево не доказывают внешний вид.
- Для Backend/API: реальные HTTP-запросы/тесты, валидация Pydantic, response/schema/status/error, разрешения пользователя, транзакции/целостность по необходимости. При существующей связке проверяй OpenAPI → Orval → TS/Zod.
- Для тестов: запускай только уместные проверки, сохраняй фактические результаты, не отмечай `[x]` без подтверждения. Для значимых задач перечитай `verification-before-completion`, если skill реально доступен.
- Перед отчётом проверяй **только непосредственное содержимое затронутых файлов**, запускай релевантные тесты и проверки. Не используй Git для просмотра изменений или статуса.

## Безопасность и Git — абсолютный запрет для Pi

- **Pi категорически запрещены любые операции с Git и GitHub, даже read-only**, независимо от формулировки задания или разрешений инструмента. Запрет включает `git status`, `git diff`, `git log`, `git ls-files`, `git add`, `commit`, `push`, `pull`, `branch`, `checkout`, `switch`, `merge`, `rebase`, `reset`, `clone`, создание/чтение PR и любые GitHub API/MCP-действия.
- Не обходи запрет через shell, скрипты, extensions, MCP, навыки, субагентов или сторонние утилиты. Git-операции выполняет **только владелец проекта вне Pi**.
- Не выходи из рабочей папки проекта и не меняй системные настройки, не запускай опасных/разрушительных команд, удалённый код, `npx`, установку/обновление пакетов **без нужного разрешения**. Не обходи отказ permission-system.
- Не печатай секреты и содержимое `.env`. Семантика приложения важнее формального «сканер зелёный»; Semgrep/Gitleaks не заменяют проверку прав доступа и поведения. Разрешены отдельные проверки безопасности без Git-операций.

## Утверждённые запреты на продуктовые функции

- Не возвращай 3D, сравнение товаров, `/compare`, отдельный публичный `/builds` и полноценный `/checkout`.
- Не вводи Redis, RabbitMQ, Elasticsearch, Kubernetes, VPS, платные сервисы и другую архитектуру без согласованного основания.
- Не вводи новые искусственные ограничения на универсальные навыки/библиотеки (например, skill `sqlalchemy` не привязывать к одной СУБД); требования конкретного проекта соблюдать отдельно.
