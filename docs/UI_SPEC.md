# UI / visual reference contract

Это **конкретные дизайн-ориентиры** для верстки. Готовые PNG находятся в `docs/references/pcbuilder/` после ручного добавления пользователем. Они являются визуальными референсами, а не готовой реализацией или источником истинных цен.

## Themes

| Токен | Тёмная Obsidian Black + Ice Blue |
| --- | --- |
| Page | `#08090C` |
| Header/Footer | `#0E1015` |
| Card | `#14171D` |
| Border | `#252932` |
| Primary text | `#F5F6F8` |
| Secondary text | `#9298A5` |
| Accent | `#67C9FF` |

Светлая тема также нужна: белый/серый фон, тёмный текст, синие акценты. Не путать акцентный синий из старых светлых референсов с финальным `#67C9FF` тёмной темы. Точные недостающие токены выбирать согласованно в рамках UI-задачи.

## Layout и общие элементы

- Desktop first как в референсах, **адаптивность** также обязательна, но точные брейкпоинты ещё не утверждены; не выдумывать «утверждённые» размеры.
- Header фиксирован `position: fixed` поверх контента на всех страницах; UI не должен прятаться под ним.
- Выпадающие меню Header выравниваются у его нижней границы; стек слоёв/drawer/backdrop — без перекрытия неверных зон.
- Логотип кликабелен; поиск интерактивен; «Товары» — единственная вкладка подсказок.
- Footer общий; страница каталога не получает лишний баннер или большой заголовок, отсутствующий в утверждённом макете.

## Критические детали по страницам

| Экран | Что должно совпасть с референсом |
| --- | --- |
| Главная | Нет hero; 2 CTA; домашние **горизонтальные** карточки 3×2 на секцию |
| Каталог | **Вертикальные** marketplace-карточки, 7×7 на широком desktop, выравнивание неполной последней строки |
| Открытые фильтры | Выезжающая панель слева под Header, затемнённый заблокированный фон, зависимые фильтры/disabled |
| Товар | Thumbnails **справа** от главного изображения, лидеры между ключом и значением в характеристиках, отзывы без лайков |
| Корзина | 2 колонки; раскрываемая сборка без двойного подсчёта её компонентов |
| Конфигуратор | 8 строк типов комплектующих, справа summary, ниже раскрываемые характеристики и действия |
| Профиль | Аватар/счётчики + секции личных данных, смены пароля и удаления |
| Вход/регистрация | **Одна модалка / два состояния**, в референсе рядом только для сравнения |
| Мои сборки | Горизонтальные карточки, стоимость/совместимость/действия, раскрытый состав как визуальная подсказка |
| Мои заказы | Карточки заказов, состав товаров и раскрытие пользовательской сборки |

## Структура взаимодействия

- Каталог: `q`, фильтры, сортировка, страница — отражены в URL, поведение имитируется Mock API с будущим серверным контрактом.
- Drawer: open/close/Escape/outside; при смене master-фильтра сбрасывать его детей.
- Компоненты конфигуратора: выбор/замена/удаление влияют на цену, совместимость, характеристики, статус допустимости действий.
- Вся интерактивность обязана проверяться в браузере, не только статическим скриншотом.

## Visual QA protocol

1. Проверить присутствие референсов (`python scripts/verify_references.py`).
2. Реально открыть соответствующий рендер (по возможности `pi-frontend-check`).
3. Получить screenshot текущего состояния, посмотреть визуально; при нужде использовать `frontend_eval` для размеров/переполнения и `frontend_console` для ошибок.
4. После любой визуальной правки — **новый screenshot**; проверить desktop и релевантные mobile/tablet viewport.
5. Для интерактивных сценариев — `frontend_act` и проверка следующего состояния. Записывать реальные результаты в `.agent/TASK.md`; не объявлять готовность без доказательства.

## Разрешение противоречий

Некоторые картинки могут показывать устаревшую 3D-функцию, сравнение товаров, «Купить сейчас», разные названия, завышенное число преимуществ и т. п. **Финальные решения из `.agent/PROJECT.md` / `docs/PRODUCT_REQUIREMENTS.md` главнее**, чем случайные детали сгенерированных иллюстраций. Но не переосмысливать остальной дизайн без запроса.
