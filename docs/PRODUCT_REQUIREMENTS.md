# Product requirements — approved scope

**Состояние:** спецификация планируемого продукта, не доказательство реализации. Любые не определённые ниже детали согласовывать при постановке соответствующей задачи, не придумывать глобально.

## Общая модель

Каталог товаров включает отдельные комплектующие, периферию, аксессуары и **публичные готовые ПК** (категория `prebuilt`). Пользовательские конфигурации из 2D-конфигуратора — **приватные объекты** пользователя, а не публичные товары.

## Header / поиск / навигация

- На каждой странице Header **fixed** к верхней границе при прокрутке; кликабельный логотип → `/`.
- Гамбургер-меню, глобальный поиск, корзина с индикатором количества, вход/аватар, пользовательское меню; выпадающие панели выровнены по нижней границе Header.
- Поиск по всему каталогу, подсказки с изображением/ценой/названием, вкладка результатов **«Товары»** (без дополнительных выдуманных вкладок), «Показать все (N)» → `/catalog?q=...`.
- Меню: главная, готовые сборки (фильтр каталога), комплектующие, периферия, аксессуары, охлаждение, сети, ПО/сервисы, акции, помощь, о нас; «Блог» **отменён**.
- Пользовательское меню: профиль/личный кабинет, заказы, приватные сборки, настройки/тёмная тема, выход. Сверять с действующими референсами.

## Главная `/`

- **Без Hero**. Вверху крупная CTA «Открыть весь каталог товаров», ниже «Собери свой ПК» → `/builder`.
- Категории товаров: готовые сборки, GPU, CPU, платы, RAM, накопители, блоки питания, корпуса и др. В каждой секции **6 компактных горизонтальных карточек, сетка 3 × 2** на широком экране (не карусель), «Смотреть все» возле заголовка.
- Блок «Почему выбирают нас»: конфигуратор ПК, редкие компоненты, готовые сборки и прочие одобренные преимущества; **никакого «Сравнения комплектующих»**.
- Footer 4 колонки: «Магазин», «Покупателям», «Контакты», «Документы» + нижняя бренд-полоска/соцсети.

## Каталог `/catalog`

- Все публичные товары (включая `prebuilt`); серверный поиск, фильтры, сортировка, пагинация через URL params.
- **На максимально широком desktop:** 7 карточек в строке × 7 строк = **49 карточек на полной странице**. Это не 7 карточек в сумме. Последняя неполная строка **центрируется**. На узких экранах адаптивное меньшее количество колонок, при этом page size остаётся 49.
- Вертикальные карточки: фото, категория/тип, название, краткое описание, рейтинг, цена, кнопка корзины; клик по карточке → `/products/:slug`.
- Drawer фильтров слева, ширина примерно 35% viewport и разумный max-width, старт ниже Header; контент затемнён и заблокирован, Header не затемнять; закрытие X/Escape/вне панели. При закрытом drawer каталог на всю ширину, только кнопка «Фильтры».
- Сортировка: новые/старые, рейтинг высокий/низкий, цена низкая/высокая.
- Мастер-категория → зависимый тип → релевантные бренд/цвет. При смене родителя сбрасывать зависимые значения; неуместные controls disabled. «Сбросить», «Применить».

## Товар `/products/:slug`

- Верх: галерея ~70% с крупным изображением и **вертикальными thumbnails справа**, блок покупки ~30% (название, цена, наличие, количество, добавление в корзину).
- Далее описание с повтором полного названия; характеристики «ключ — линия между — значение», «Все характеристики» раскрывает список; отзывы с аватаром, именем, оценкой/звёздами и комментариями.
- **Без лайков/дизлайков отзывов и любых кнопок «Сравнить».**

## Корзина `/cart`

- Основной список слева (~70%), сводка справа (~30%). Обычные позиции: фото, название, спецификация, количество +/−, сумма, удалить.
- Пользовательская сборка — **одна позиция** с раскрываемым списком комплектующих (комплектующие внутри не учитываются второй раз).
- «Купить» **не ведёт на `/checkout`**: простой сценарий «Спасибо!» без форм и реальной оплаты; оформленная демо-покупка попадает в историю заказов. Состояние пустой корзины — отдельное отображение.

## 2D-конфигуратор `/builder`

- 8 категорий: CPU, материнская плата, видеокарта, RAM, накопитель, БП, корпус, охлаждение. Для каждой: выбранная деталь с изображением/ценой/характеристиками, «Заменить», «Удалить»; или «Выбрать».
- В правой сводке выбранные позиции, совместимость, итог, оценка энергопотребления **только при валидных исходных данных**; действие «Добавить сборку в корзину» при допустимом состоянии.
- Ниже раскрываемая таблица актуальных характеристик сборки и кнопки «Создать сборку», «Сохранить сборку», «Очистить».
- При редактировании сборки обновлять её комплектующие, совместимость, цену и характеристики; приватность обеспечивается Backend.
- **3D-компонент и WebGL не делать.**

## Учётная запись / авторизация

- `/account`: аватар, имя/email, счётчики покупок и отзывов, редактирование личных данных, изменение пароля (старый/новый/повтор с видимостью), удаление профиля с подтверждением.
- Вход/регистрация — **одно модальное окно с переключаемым режимом**, закрывается крестиком, по Escape/снаружи. Вход: «Email или имя пользователя», «Пароль», «Войти», ссылка «Зарегистрироваться».
- Регистрация: «Email», «Имя пользователя», «Пароль», «Повторите пароль», «Зарегистрироваться», ссылка «Войти». Ошибки у полей; глазки для паролей; без social auth по умолчанию.

## «Мои сборки» (приватные)

- Список горизонтальных карточек сохранённых сборок: название, время, изображение, стоимость, статус совместимости и состав; действия «Создать», «Открыть/Изменить», «В корзину», «Удалить» с подтверждением.
- «Открыть/Изменить» → `/builder` с сохранённым состоянием; отдельная подробная страница сборки не нужна.
- Незавершённая/несовместимая сборка не добавляется в корзину; пустое состояние с CTA.
- Владелец видит и изменяет **только свои** сохранённые конфигурации; Backend проверяет ownership на каждой соответствующей операции.

## «Мои заказы» (приватные)

- Простая история **демонстрационных** покупок: №, дата, сумма, статус «Завершён (демо)», товары, изображения, количества/цены; вложенная пользовательская сборка раскрывает список своих частей.
- После «Купить» создаётся демо-запись; стоимость и состав — **исторический снимок (snapshot)** на момент покупки. Счётчик покупок в профиле отображает реальные демо-записи аккаунта.
- Нет реального платежа, доставки, трекинга, возвратов или отдельной страницы заказа.

## Безопасность и сохранность данных

- Серверные permissions важнее сокрытия кнопок на Frontend. Учесть гонки, транзакции, корректные проверки данных, остатки/цены по согласованной бизнес-логике.
- Детали поведения без явного решения пользователя не дополнять произвольно: например, поведение гостевой демо-покупки и точные маршруты приватных разделов обсуждать в scope соответствующей задачи.
