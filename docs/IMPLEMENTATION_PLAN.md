# Implementation roadmap — not an active task

Этапы описывают утверждённую последовательность. **Не запускать все этапы автоматически и не считать пункты выполненными.** Каждое задание Pi — отдельный компактный scope с `.agent/TASK.md`, skills, checkpoints, проверкой runtime и отчётом.

## 1. Frontend с Mock API

- Инициализировать Vite/React/TypeScript по отдельному разрешённому заданию.
- Согласовать токены обеих тем, Header/Footer, маршруты, общие UI компоненты.
- Реализовывать страницы по референсам: главная → каталог/фильтры/поиск → товар → корзина → 2D builder → auth → профиль → приватные сборки/заказы.
- Тестировать интерактивность, URL-state и адаптивность; **каждый значимый UI шаг подтверждать свежими реальными скриншотами**.
- Не подменять реальные API-запросы старыми жестко зашитыми данными после подключения backend.

## 2. Backend и БД

- Отдельными задачами: schema/ORM/migrations, каталог и серверный поиск, auth/ownership, сборки/совместимость, корзина/демо-заказы, отзывы/профиль.
- Для API проверять вход/выход/error, авторизацию, concurrency/transaction integrity и фактические HTTP-тесты.
- Разрешение на установку зависимостей/изменение окружения не предполагать автоматически.

## 3. Интеграция и финал

- OpenAPI → Orval → клиент/типы/Zod, TanStack Query invalidation и состояния загрузки/ошибок.
- UI и Backend E2E, Docker Compose, документация локального запуска, GitHub README/медиа.
- Git commit/push/PR — только по запросу владельца, отдельно от разработки.

## Для каждого шага Pi

1. Read-only discovery + global/project AGENTS + PROJECT.
2. Выбрать релевантные skills, найти и прочитать все нужные реальные SKILL.md.
3. До edits создать/актуализировать `.agent/TASK.md`, точные критерии и контрольные точки.
4. Минимальная реализация и реальные runtime/test/visual/security проверки по scope.
5. Проверить `git diff`; чекбоксы закрывать **после** полученных evidence; затем отчёт без преувеличений.
