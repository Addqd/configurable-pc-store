# PC Builder — проверка совместимости на backend

Реализация: `backend/app/services/compatibility.py`. Источник данных — **только** `products.technical_specs` (JSONB), а не текст названия или строки описания. Существующие 51 демотовар не изменяются. У них отсутствуют необходимые проверенные характеристики, поэтому для таких сборок `unknown` — ожидаемый результат.

## Статусы

- `incompatible` — доказан конкретный конфликт: неправильная категория, несовпадающие сокеты, размеры, мощности, разъёмы и т. п.
- `unknown` — нет хотя бы одного из восьми компонентов либо недостаточно *структурированных* данных для одной из обязательных проверок.
- `compatible` — все восемь компонентов выбраны, правильные категории и **все реализованные проверки** подтверждены. Это проверка по доступным данным, а не универсальная гарантия совместимости произвольного оборудования.

Если обнаружен подтверждённый конфликт, он имеет приоритет над неизвестными значениями. Результат содержит отдельные строки с `slot`, `status`, `message` для диагностики.

## Договорённость по техническим характеристикам

Ключи чувствительны к написанию. Значения текстовых идентификаторов и их массивы сравниваются без учёта регистра, пробелы по краям игнорируются. Числа — положительные JSON-числа, **не строки и не логические значения**. Массивы разъёмов повторяют элементы по количеству (например, два `"8pin"`). Для каждого ключа требуются проверенные данные производителя или инженерно верифицированные сведения; нельзя заполнять их догадками, чтобы принудительно получить `compatible`.

| Категория | Обязательные поля `technical_specs` для соответствующих проверок |
|---|---|
| `cpu` | `socket`, `model_id`, `thermal_design_power_w`, `max_power_draw_w` |
| `mobo` | `socket`, `supported_cpu_models: string[]`, `memory_type`, `max_memory_gb`, `ram_slots`, `form_factor`, `gpu_interfaces: string[]`, `storage_interfaces: string[]`, `supported_nvme_lengths_mm: number[]` для NVMe, `required_cpu_power_connectors: string[]`, `required_board_power_connectors: string[]`, `max_power_draw_w` |
| `gpu` | `interface`, `length_mm`, `thickness_slots`, `required_power_connectors: string[]`, `max_power_draw_w` |
| `ram` | `memory_type`, `capacity_gb` (общая ёмкость комплекта), `module_count`, `height_mm` для воздушного кулера, `max_power_draw_w` |
| `storage` | `interface` (`nvme` либо `sata`), `length_mm` (для NVMe), `drive_form_factor` (для SATA), `max_power_draw_w` |
| `psu` | `wattage_w` (выходная мощность), `form_factor`, `length_mm`, `available_gpu_power_connectors: string[]`, `available_cpu_power_connectors: string[]`, `available_board_power_connectors: string[]` |
| `case` | `supported_motherboard_form_factors: string[]`, `max_gpu_length_mm`, `max_gpu_thickness_slots`, `max_cooler_height_mm` для воздушного кулера, `supported_radiator_sizes_mm: number[]` для СЖО, `supported_drive_form_factors: string[]` для SATA, `supported_psu_form_factors: string[]`, `max_psu_length_mm`, `max_power_draw_w` (вентиляторы и иные потребители корпуса) |
| `cooling` | `supported_sockets: string[]`, `cooling_capacity_w`, `cooling_type` (`air` или `liquid`), `height_mm` и `ram_clearance_mm` для воздушного, `radiator_size_mm` для жидкостного, `max_power_draw_w` |

Проверяемые интерфейсы записываются единообразно, например: `"pcie_x16"`, `"nvme"`, `"sata"`. Это **физический тип интерфейса**, а не версия PCIe. `model_id` CPU и элементы `supported_cpu_models` должны быть одним и тем же проверенным идентификатором модели, совместимым с нужной ревизией BIOS платы.

Номинальная мощность PSU сравнивается с **суммой документированных максимальных электрических нагрузок** CPU, платы, GPU, RAM, накопителя, охлаждения и корпуса с дополнительным запасом 20%. Запас — явное консервативное правило нашей проверки, а не характеристика производителя. `TDP` CPU не приравнивается к максимальному потреблению. Если хотя бы одна нагрузка неизвестна, проверка мощности возвращает `unknown`.

Разъёмы питания проверяются по типу **и количеству**; наличие адаптеров не подразумевается. Для NVMe проверяется физическая длина накопителя, для SATA — размер отсека. Для охлаждения проверяются сокеты, тепловая мощность и физическая установка (включая RAM clearance у воздушного кулера или размещение радиатора СЖО).

### Важные границы

- Достоверность характеристик и актуальность CPU BIOS support list должна подтверждаться источниками при наполнении каталога. Движок не занимается их сбором и не подменяет недостающие данные.
- Нестандартные корпуса, пассивное охлаждение, райзеры, переходники, экстремальный разгон, сложные ограничения по линиям PCIe и особенности кабельного менеджмента требуют отдельных подтверждённых правил; нельзя без проверки объявлять их подходящими.
- `compatible` означает прохождение **реализованного набора проверок**, а не заменяет инструкции производителя и тестирование сборки.
- `cart_service._build_snapshot()` использует тот же `check_selections()`. Незавершённые, неизвестные и несовместимые сборки не попадают в демо-заказ.
- Для дальнейшего развития можно добавлять новые строго проверяемые правила в `compatibility.py` и тестовые фикстуры без изменения API-контракта.
