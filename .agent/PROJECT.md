# PC Builder & Store — persistent project context

**Статус (27.10.2026):** согласованы функциональность, дизайн-референсы и стек; работающего кода ещё нет. Это **запланированный продукт**, а не описание найденного runtime. Перед существенными задачами проверить фактические локальные файлы и обновить только подтверждённые изменения.

## Цель

Полноценный, убедительный Full-Stack-проект для портфолио: каталог комплектующих и готовых ПК, 2D-конфигуратор с проверкой совместимости, корзина, личный кабинет, приватные сохранённые сборки и история **демонстрационных** заказов. Приоритет — качество, проверяемость и быстрое завершение, а не искусственное наращивание функционала.

## Утверждённый стек

- Frontend: **React, TypeScript, Vite, Tailwind CSS, Zustand, Zod, React Router, TanStack Query, Orval**; React Hook Form допустим для форм.
- Backend: **Python, FastAPI, Pydantic, SQLAlchemy 2.x, Alembic, psycopg, PyJWT, pwdlib + Argon2**.
- Данные: **PostgreSQL**, поиск **PostgreSQL Full-Text Search + pg_trgm**.
- Запуск: **Docker + Docker Compose** (локально), исходники/демо — **GitHub**.
- Проверки: **Vitest, React Testing Library, pytest, HTTPX**; **Playwright, GitHub Actions** — опционально по задаче.
- Redis — опционально позднее, только после согласованного решения; для старта не нужен.

## Режим работы / конвейер

1. Реализовать frontend по референсам с Mock API и согласованными контрактами.
2. Реализовать FastAPI + PostgreSQL, бизнес-логику, auth, данные, тесты.
3. Интегрировать OpenAPI FastAPI через Orval для TypeScript/Zod/API-клиента и TanStack Query.
4. Проверить frontend/backend/end-to-end, подготовить Docker Compose, README, воспроизводимый локальный запуск и GitHub-портфолио.

## Навигация (подтверждено)

- `/` — главная.
- `/catalog` — общий каталог, фильтры и поиск, включая готовые ПК.
- `/products/:slug` — страница товара.
- `/cart` — корзина.
- `/builder` — **2D** конфигуратор.
- `/account` — профиль.
- «Мои сборки» и «Мои заказы» — приватные разделы, **точные пути пока не утверждены**; не придумывать окончательные URL без задачи.
- Вход и регистрация — **модальные режимы одного окна**, не отдельные страницы.

## Не менять без явного решения

- 3D/WebGL/GLB отменены. Только 2D список деталей с выбором/заменой.
- Сравнение отменено полностью: никаких `/compare`, кнопок и преимуществ с этой функцией.
- Публичные готовые сборки являются **обычными товарами** категории `prebuilt` в `/catalog`, не `/builds`.
- Сохранённые пользовательские сборки **приватные**; сервер обеспечивает ownership/authorization, не только frontend.
- `/checkout` отменён: «Купить» → простой «Спасибо!» без форм оплаты/доставки, демонстрационная запись заказа.
- Никакого VPS/платного деплоя по умолчанию; GitHub + локальная демонстрация.
- «Блог» удалён из запланированного меню.

## Дизайн-система

**Основная тёмная тема: Obsidian Black + Ice Blue**. Фон `#08090C`, Header/Footer `#0E1015`, карточки `#14171D`, границы `#252932`, основной текст `#F5F6F8`, вторичный `#9298A5`, акцент `#67C9FF`.

**Светлая тема:** светлые/белые поверхности, тёмные надписи, синий акцент. Светлые референсы служат образцами; не переносить случайные несовместимые элементы между темами. Итоговый рендер обязательно проверять.

## Core invariants

- Фиксированный Header и общая навигация; общие состояния UI — Zustand, серверные данные/кеш — TanStack Query.
- Поиск по всем товарам на сервере (Full-Text Search + pg_trgm), включая готовые сборки; в mock-этапе — аналогичный контракт.
- Каталог: **49 товаров/страница** (7 колонок × минимум 7 строк при заполненной странице на максимально широком desktop); неполная последняя строка по центру, адаптивность на меньших экранах.
- Фильтры зависимые: master-категория → тип → цвет/производитель, сброс зависимых значений при изменении родителя.
- Корзина считает пользовательскую сборку **одной позицией**, с раскрываемым составом; не суммирует вложенные компоненты повторно.
- Создаваемые/сохранённые сборки строго приватны; проверки совместимости и права доступа — настоящие правила backend, не UI-условности.
- История демонстрационных заказов приватна; цены/количества/состав покупки должны храниться как snapshot на момент оформления, а не пересчитываться на текущем каталоге.
- Периоды, цены, товары, наличие и статусы на референсах — вымышленные примеры, не реальные API-данные.
